# План реализации голосового ассистента

## 1. Результат

Публичный web-сервис без регистрации, в котором пользователь может написать
или продиктовать запрос на русском языке и выполнить четыре действия:

1. Создать задачу или напоминание.
2. Создать встречу.
3. Получить события за период.
4. Найти ранее созданное событие.

Приложение разворачивается на одном VPS через Docker Compose. Backend, frontend
и SQLite работают как единый небольшой сервис. Отдельные микросервисы, MCP,
очереди, Redis, векторная база и полноценный RAG в первой версии не нужны.

## 2. Архитектура

```text
Браузер
  ├─ текстовый ввод
  ├─ MediaRecorder (WebM/Opus)
  ├─ история диалога
  └─ browser speechSynthesis
             │ HTTPS/JSON или multipart
             ▼
FastAPI
  ├─ API endpoints
  ├─ anonymous session
  ├─ dialogue state
  ├─ GigaChat adapter
  ├─ command router
  ├─ event service
  └─ SQLAlchemy repositories
             │
             ▼
          SQLite
```

GigaChat не обращается к базе и не выполняет функции приложения. Он только
преобразует свободную фразу или аудио в ограниченную JSON-команду. Backend
валидирует команду через Pydantic и вызывает обычный Python-обработчик.

```text
запрос → GigaChat JSON Schema → Pydantic → router → service → SQLite → ответ
```

## 3. Стек

- Python 3.12;
- FastAPI и Uvicorn;
- SQLAlchemy 2;
- Alembic;
- SQLite;
- Pydantic Settings;
- HTTPX или официальный Python SDK GigaChat;
- pytest;
- простой frontend на HTML, CSS и TypeScript/JavaScript;
- Docker Compose;
- Caddy или Nginx для HTTPS.

Отдельный React/Next.js-проект на старте не требуется. Один статический frontend
в составе FastAPI уменьшает число процессов, настроек и проблем при деплое.
Если интерфейс разрастется, его можно отделить позднее.

## 5. Модель данных

### `events`

```text
id                    integer primary key
owner_session_id      string nullable
source                seed | user_text | user_audio
type                  task | reminder | meeting
title                 string
description           string nullable
starts_at             datetime nullable
ends_at               datetime nullable
due_at                datetime nullable
timezone              string
status                pending | completed | cancelled
raw_user_text         string nullable
tags                   JSON-text or normalized string
created_at            datetime
updated_at            datetime
```

`owner_session_id = NULL` означает общую seed-запись из CSV. Пользователь видит
общие seed-записи и записи своей анонимной сессии.

### `dialogue_sessions`

```text
session_id             string primary key
pending_action         JSON nullable
last_referenced_event_id integer nullable
created_at             datetime
updated_at             datetime
```

### `messages` — необязательно для MVP

Историю на первом этапе можно держать в браузере. Таблица нужна только если
история должна сохраняться после очистки localStorage или между устройствами.

## 6. Анонимная сессия

При первом открытии браузер создает UUID и сохраняет его в `localStorage`.
Каждый запрос передает UUID в заголовке `X-Session-ID`.

Backend:

1. Проверяет формат UUID.
2. Создает `dialogue_sessions`, если записи еще нет.
3. Использует UUID как владельца новых событий.

IP-адрес не используется как идентификатор.

## 7. Формат команды от GigaChat

Используем `response_format.type=json_schema`, а не агентный цикл и не MCP.

```json
{
  "action": "create_task | create_meeting | list_events | search_events | clarify",
  "transcript": "исходная фраза пользователя",
  "title": null,
  "event_type": null,
  "starts_at": null,
  "ends_at": null,
  "due_at": null,
  "date_from": null,
  "date_to": null,
  "query": null,
  "missing_fields": [],
  "clarification_question": null
}
```

В системный промпт всегда передаются:

- текущие дата и время;
- `Europe/Moscow`;
- начало недели в понедельник;
- описание разрешенных действий;
- правило не выдумывать отсутствующие обязательные значения;
- сохраненное `pending_action`, если идет уточняющий диалог.

Pydantic дополнительно проверяет:

- действие входит в разрешенный enum;
- у встречи есть время начала;
- у задачи есть заголовок;
- конец периода не раньше начала;
- дата и время имеют корректный ISO-8601 формат;
- неизвестные поля запрещены.

## 8. Обработка текстового запроса

```text
POST /api/assistant/text
  → проверить session ID и текст
  → получить pending_action
  → запросить JSON-команду у GigaChat
  → провалидировать Pydantic
  → при нехватке данных сохранить pending_action и вернуть вопрос
  → иначе вызвать обработчик команды
  → очистить pending_action
  → вернуть текст ответа и данные события
```

Пример ответа API:

```json
{
  "reply": "Встреча с Иваном добавлена на завтра, 15:00.",
  "action": "create_meeting",
  "events": [],
  "created_event": {
    "id": 42,
    "title": "Встреча с Иваном",
    "starts_at": "2026-10-11T15:00:00+03:00"
  },
  "needs_clarification": false
}
```

## 9. Обработка аудио

```text
POST /api/assistant/audio (multipart/form-data)
  → проверить MIME-тип и размер
  → передать файл в Polza POST /audio/transcriptions
  → получить transcript от openai/whisper-large-v3-turbo
  → передать transcript в текстовый интерпретатор GigaChat
  → выполнить общий pipeline команды
```

Frontend записывает `audio/webm;codecs=opus`. Если Polza стабильно принимает
записи браузера, FFmpeg не нужен. Конвертацию добавляем только при подтверждённой
проблеме совместимости.

Поле `transcript` показывается в истории, чтобы пользователь видел, как была
распознана речь.

## 10. Обработчики команд

Router содержит явное отображение:

```python
handlers = {
    "create_task": event_service.create_task,
    "create_meeting": event_service.create_meeting,
    "list_events": event_service.list_events,
    "search_events": search_service.search_events,
}
```

Обработчики не знают о GigaChat и работают с обычными типизированными входными
моделями. Их можно полностью тестировать без сети.

## 11. Уточняющий диалог

Пример:

```text
Пользователь: Добавь встречу с Иваном завтра.
Ассистент: На какое время поставить встречу?
Пользователь: В 15:00.
Ассистент: Встреча с Иваном добавлена на завтра, 15:00.
```

После первого запроса сохраняется:

```json
{
  "action": "create_meeting",
  "title": "Встреча с Иваном",
  "starts_at": "2026-10-11",
  "missing_fields": ["start_time"]
}
```

Второй запрос отправляется в GigaChat вместе с этим объектом. Полученный полный
объект валидируется и только затем записывается в SQLite. Pending state имеет
срок жизни, например 30 минут, после чего начинается новая команда.

## 12. Поиск

Первая версия использует простой и объяснимый поиск:

1. Нормализация строки: lowercase, `ё → е`, удаление лишней пунктуации.
2. Выделение тегов из заголовка при импорте и создании.
3. Фильтрация по владельцу, типу события и датам.
4. Совпадение по заголовку, описанию и тегам через `LIKE`.
5. Ранжирование: точное совпадение → совпадение тегов → частичное совпадение.

SQLite FTS5 добавляется только если обычного поиска окажется недостаточно.
Embeddings/RAG не входят в первый этап.

## 13. Импорт CSV

Скрипт `scripts/import_seed.py`:

1. Читает CSV как UTF-8 с BOM.
2. Объединяет `date` и `time`.
3. Выбирает предварительный тип по простым правилам.
4. Формирует теги из текста.
5. Записывает событие с `source=seed` и `owner_session_id=NULL`.
6. Использует исходный CSV ID или отдельный `source_id`, чтобы повторный запуск
   не создавал дубликаты.

Ошибочные падежи и формулировки в исходных данных не исправляются; оригинальный
текст сохраняется.

## 14. HTTP API

Минимальные endpoints:

```text
GET  /                       web-интерфейс
GET  /api/health             состояние приложения и БД
POST /api/assistant/text     текстовая команда
POST /api/assistant/audio    аудиокоманда
GET  /api/events             события с фильтрами
```

Отдельные CRUD-endpoints для редактирования и удаления добавляются только после
готовности обязательных сценариев.

## 15. Интерфейс

Одна страница:

- история сообщений;
- текстовое поле;
- кнопка отправки;
- кнопка записи/остановки аудио;
- индикатор обработки;
- карточки найденных или созданных событий;
- понятное сообщение об ошибке;
- переключатель озвучивания ответа.

Озвучивание выполняется через browser `speechSynthesis`. Это не часть backend и
не требует дополнительного ключа.

## 16. Ошибки и безопасность

- Ограничить длину текста и размер аудио на backend.
- Принимать только разрешенные MIME-типы.
- Не вставлять ответ модели в SQL или HTML без обработки.
- Использовать SQLAlchemy parameters, а не ручное составление SQL.
- Добавить timeout и один контролируемый retry для GigaChat.
- Не создавать событие при невалидном или неоднозначном ответе модели.
- Не отдавать пользователю traceback.
- Не логировать ключи и полный Authorization header.
- Добавить `.env`, `*.db`, временное аудио и логи в `.gitignore`.
- На VPS хранить `.env` с правами `600`.

## 17. Тесты

Минимальный набор:

### Unit

- роутинг каждой JSON-команды;
- валидация обязательных полей;
- правила дат и длительности встречи;
- продолжение и очистка pending action;
- ранжирование поиска;
- идемпотентный импорт CSV.

### Integration

- создать задачу и прочитать ее;
- создать встречу после уточнения времени;
- получить события за период;
- найти seed-событие;
- изоляция двух session ID;
- обработка невалидного ответа GigaChat через mock.

Тесты относительных дат используют фиксированное текущее время.

### Manual smoke test перед публикацией

- `Напомни завтра в 10 позвонить Ивану`;
- `В пятницу нужно отправить отчет`;
- `Добавь встречу с командой завтра` → уточнение времени;
- `Что у меня на этой неделе?`;
- `Найди задачу про договор`;
- короткая голосовая версия каждого основного сценария.

## 20. Основной принцип

Сложность должна оставаться в понимании естественного языка, а не в
инфраструктуре. Один backend, одна SQLite-база, один внешний AI-провайдер и один
простой frontend достаточны для качественного выполнения тестового задания.
