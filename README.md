# Голосовой помощник для задач, встреч и напоминаний

Сделано командой «Триада» для GorkyCode.

Прототип принимает свободные текстовые и голосовые команды, создаёт задачи,
напоминания и встречи, показывает планы за период, ищет и изменяет сохранённые
события.

Публичная версия: https://195-19-213-247.regru.cloud/

## Архитектура

```text
браузер → FastAPI → бизнес-правила → SQLAlchemy → SQLite
              ├── GigaChat: извлечение действия и аргументов
              └── Polza Whisper: преобразование аудио в текст
```

GigaChat предлагает структурированную команду, но не обращается к базе данных.
Backend валидирует результат через Pydantic, проверяет обязательные поля,
прошедшие даты и конфликты встреч и только затем меняет данные. Поиск выполняется
детерминированно по нормализованному тексту и тегам без embeddings и RAG.

Анонимный UUID из `localStorage` изолирует данные браузерной сессии. События и
незавершённые действия хранятся в SQLite, а последние 60 сообщений интерфейса —
в `localStorage`.

## Локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m scripts.migrate
uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000`. Для обработки текстовых команд заполните
`GIGACHAT_AUTH_KEY` в `.env`. Для голосового ввода также укажите
`POLZA_API_KEY`: аудио распознаётся моделью
`openai/whisper-large-v3-turbo` через Polza, после чего полученный текст
обрабатывается тем же путём, что и обычная текстовая команда.

Swagger-документация доступна по `/docs`, проверка состояния — по
`/api/health`.

Голосовой поток:

```text
браузер → POST /api/assistant/audio → Polza Whisper → текст → GigaChat → команда
```

По умолчанию используются:

```dotenv
POLZA_API_URL=https://polza.ai/api/v1
POLZA_STT_MODEL=openai/whisper-large-v3-turbo
POLZA_STT_LANGUAGE=ru
DIALOGUE_TTL_MINUTES=30
```

Ключ Polza должен начинаться с `pza_`. Он хранится только в `.env` и никогда
не передаётся браузеру. Приложение принимает короткие записи WebM/Opus, OGG,
MP3, MP4/M4A и WAV размером до `MAX_AUDIO_BYTES`. Если конкретный браузерный
WebM будет отклонён провайдером, потребуется отдельная конвертация через FFmpeg;
в текущую версию она намеренно не включена.

Для записи голоса странице необходим HTTPS либо локальный адрес. В Chrome или
Edge разрешите доступ к микрофону для сайта. Переключатель озвучивания ответов
использует браузерный `speechSynthesis` и не требует отдельного API-ключа.

## Docker

```bash
cp .env.example .env
docker compose up -d --build
```

SQLite хранится в persistent Docker volume и не пропадает при перезапуске
контейнера. При старте контейнер автоматически применяет миграции Alembic.
Команда `python -m scripts.migrate` также безопасно принимает старую базу,
ранее созданную приложением через `create_all()`, если её схема совместима.
Seed-данные и внешний CSV не используются. Перед приложением следует настроить
Caddy или Nginx с HTTPS: браузер предоставляет микрофон только в безопасном
контексте.

## Проверка

```bash
pytest -q
```

Примеры запросов:

- `Напомни завтра в 10 позвонить Ивану`;
- `Добавь встречу с командой завтра в 15:00`;
- `Что у меня на этой неделе?`;
- `Найди задачу про договор`;
- `Я когда-то ставил задачу по договору, найди её`;
- `Перенеси встречу с командой на завтра в 17:00`.

## Принятые правила и ограничения

- Часовой пояс — `Europe/Moscow`, неделя начинается в понедельник.
- Задача может не иметь точного времени; встрече и напоминанию время нужно.
- `В пятницу` в саму пятницу означает следующую пятницу; для текущего дня
  используется `сегодня`.
- Пересекающаяся встреча создаётся только после явного подтверждения.
- Отменённые записи скрываются, но физически остаются в SQLite.
- Повторяющиеся события, реальные уведомления и календарные интеграции не входят
  в MVP.
- Широкая конвертация аудиоформатов через FFmpeg пока не реализована.
- Seed-датасет не используется: тесты создают изолированные данные сами.

Подробные решения и порядок разработки описаны в `IMPLEMENTATION_PLAN.md`.
