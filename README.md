# Голосовой помощник для задач, встреч и напоминаний

Сделано командой «Триада» для GorkyCode.

Прототип принимает обычные русские текстовые и голосовые команды, сохраняет
события и поддерживает уточняющий диалог. Готовую версию лучше проверять здесь:

**https://195-19-213-247.regru.cloud/**

> Сервис размещён на бесплатном хостинге. Во время тестирования были случаи,
> когда сервер временно становился недоступен и самостоятельно восстанавливался
> в течение часа. Если возникла ошибка подключения или задержка ответа,
> попробуйте открыть сервис позже.

Локальный интерфейс без настроенных внешних API откроется, но создание и
интерпретация свободных команд работать не будут. Публичная версия уже
настроена, доступна по HTTPS и подходит для проверки микрофона.

## Возможности

- создание задач, напоминаний и встреч из свободной фразы;
- голосовой ввод через Polza Whisper Turbo;
- уточнение отсутствующих названия, даты или времени с сохранением контекста;
- списки за день или период и детерминированный поиск по нескольким словам;
- понимание относительных дат и времени: `завтра`, `в пятницу`,
  `через два часа`, `следующая неделя` и другие поддержанные варианты;
- редактирование, перенос, мягкое удаление и отметка задач/напоминаний
  выполненными — голосом, текстом или кнопками карточки;
- предупреждение и подтверждение при пересечении встреч;
- отдельная адаптивная карточка расписания дня по запросу
  `Покажи расписание на завтра`: события сортируются по времени, задачи без
  времени выводятся в блоке «В течение дня»;
- сохранение событий, незавершённого диалога и последних 60 сообщений;
- анонимная изоляция пользователей по UUID браузерной сессии;
- адаптивный интерфейс, восстановление истории после обновления и необязательная
  озвучка ответов средствами браузера.

## Как это устроено

```text
браузер → FastAPI → бизнес-правила → SQLAlchemy → SQLite
              ├── GigaChat: разбор свободной команды
              └── Polza Whisper Turbo: распознавание аудио
```

GigaChat возвращает только структурированное намерение и аргументы. Backend
проверяет их через Pydantic, валидирует даты, обязательные поля и конфликты и
только после этого изменяет SQLite. Поиск и карточка дня работают
детерминированно, без embeddings, RAG и доступа модели к базе данных.

## Быстрое развёртывание через Docker

Требуются Docker, Docker Compose, домен и HTTPS reverse proxy.

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd <ПАПКА_ПРОЕКТА>
cp .env.example .env
```

Заполните в `.env` как минимум:

```dotenv
GIGACHAT_AUTH_KEY=<актуальный Authorization key GigaChat>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
POLZA_API_KEY=<ключ Polza с префиксом pza_>
```

Остальные значения уже имеют рабочие значения по умолчанию. Затем:

```bash
docker compose up -d --build
docker compose logs -f app
```

Контейнер сам применяет Alembic-миграции и слушает `127.0.0.1:8000`. SQLite
хранится в persistent volume `assistant-data` и не исчезает после перезапуска.

Проверка:

```bash
curl http://127.0.0.1:8000/api/health
```

Ожидаемый ответ: `{"status":"ok"}`. Для обновления версии:

```bash
git pull
docker compose up -d --build
```

## Ручное развёртывание на VPS

Вариант без Docker для Ubuntu/Debian и Python 3.12:

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd <ПАПКА_ПРОЕКТА>
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
# заполнить GIGACHAT_AUTH_KEY и POLZA_API_KEY
.venv/bin/python -m scripts.migrate
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Для постоянной работы запускайте ту же команду через systemd с
`WorkingDirectory`, указывающим на корень проекта. После обновления:

```bash
cd <ПАПКА_ПРОЕКТА>
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m scripts.migrate
sudo systemctl restart <ИМЯ_СЕРВИСА>
sudo systemctl status <ИМЯ_СЕРВИСА> --no-pager
```

Перед приложением настройте Nginx или Caddy. Минимальный фрагмент Nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Подключите сертификат для домена. Без HTTPS микрофон на удалённом сайте браузер
не предоставит. Сам Uvicorn наружу открывать не нужно: порт 8000 должен
оставаться локальным, а публичные запросы принимает reverse proxy.

## Локальный запуск и предосторожности

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m scripts.migrate
uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000`; Swagger находится на `/docs`, healthcheck —
на `/api/health`.

Перед локальной проверкой учтите:

1. **Запускайте команды из корня проекта.** При запуске Uvicorn из `data/`
   импорт `app` завершится ошибкой, а относительный путь SQLite укажет не туда.
2. **Нужны обе внешние интеграции.** GigaChat используется для свободных
   текстовых команд, Polza — для транскрибации голоса. Нужны действующие ключи,
   интернет, доступ к API и доступная квота. Старый ключ GigaChat может быть
   отозван или относиться к другому scope.
3. **Не публикуйте `.env`.** Он исключён из Git. Ключи должны оставаться только
   на backend; после случайной публикации их необходимо перевыпустить.
4. **Не отключайте проверку TLS в рабочем окружении.** Оставляйте
   `GIGACHAT_VERIFY_SSL=true`. Отключение допустимо только как временная
   локальная диагностика проблем сертификатов.
5. **Микрофон работает только на `localhost` или через HTTPS.** Обычный
   `http://<IP-сервера>` не является безопасным контекстом. Разрешите доступ к
   микрофону в настройках браузера.
6. **Аудио зависит от браузера и провайдера.** Поддерживаются короткие WebM/Opus,
   OGG, MP3, MP4/M4A и WAV до `MAX_AUDIO_BYTES`. FFmpeg-конвертация в MVP не
   включена, поэтому экзотический формат может быть отклонён.
7. **Локальные данные сохраняются.** По умолчанию используется
   `data/assistant.db`, а UUID и история остаются в `localStorage`. Для
   изолированного эксперимента задайте отдельный `DATABASE_URL` и используйте
   новую браузерную сессию.
8. **`--reload` предназначен только для разработки.** На VPS запускайте Uvicorn
   без него. Приложение не создаёт схему при старте — перед первым запуском и
   после обновления обязательно выполняйте `python -m scripts.migrate`.
9. **Не запускайте несколько Uvicorn workers с одной SQLite.** Для прототипа
   достаточно одного процесса за Nginx/Caddy. Перед миграциями и обновлением
   рабочей версии сделайте резервную копию файла БД или Docker volume.

Из-за зависимости от ключей, квот, сети, HTTPS и разрешения микрофона для
функциональной проверки рекомендуется публичная версия, а локальный запуск —
для разработки и автотестов.


Примеры команд:

- `Напомни завтра в 10 позвонить Ивану`;
- `Добавь встречу с командой завтра в 15:00`;
- `Что у меня на следующей неделе?`;
- `Найди задачу про договор`;
- `Перенеси встречу с командой на завтра в 17:00`;
- `Покажи расписание на завтра`.

## Ограничения MVP

- часовой пояс фиксирован как `Europe/Moscow`, неделя начинается в понедельник;
- у задачи время необязательно, у встречи и напоминания обязательно;
- пересекающиеся встречи требуют подтверждения;
- удаление мягкое: запись остаётся в базе со статусом `cancelled`;
- озвучка ответа выполняется браузерным `speechSynthesis`
